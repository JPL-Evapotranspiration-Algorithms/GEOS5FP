# GEOS5FP Development Plan

## Objective
Resolve critical failures caused by missing GDAL HDF5/NetCDF4 plugins (`gdal_HDF5.so`) in containerized environments, eliminate the subprocess `ImportError` crash during validation, and restore full support for raster snapshot routing, `MultiPoint` queries, and computed albedo variables (`albedo_visible`, `albedo_NIR`).

---

## Phase 1: `netCDF4`-Based File Validation & Subprocess Error Handling
**Target File:** `GEOS5FP/validate_GEOS5FP_NetCDF_file.py`

### 1.1 Switch Primary NetCDF Validation from GDAL (`rasterio`) to `netCDF4`
* **Why:** `rasterio.open()` fails when `gdal_HDF5.so` is absent, causing valid `.nc4` granules to be rejected and deleted in a retry loop. `netCDF4` is already a core package dependency in `pyproject.toml`.
* **Implementation Steps:**
  1. Update `_validate_direct()` to open the file using `netCDF4.Dataset(expanded_filename, mode="r")` as the primary validation path instead of `rasterio.open()`.
  2. Extract and populate metadata:
     * `driver`: `nc_ds.file_format` (e.g., `NETCDF4`)
     * `variable_names` & `subdatasets`: 2D+ variables in `nc_ds.variables`
     * `width` & `height`: inferred from `lon`/`lat` dimensions
     * `bounds`: computed from `min`/`max` of `lon` and `lat` coordinate variables (checking against valid global geographic bounds `[-180.1, 180.1]` and `[-90.1, 90.1]`)
  3. Validate `required_variables` directly against `nc_ds.variables.keys()`.
  4. When `check_data_integrity=True`, read a `100 x 100` slice of the first 2D+ variable using `np.ma.filled(var[slices], np.nan)` and compute `sample_valid_data_ratio`.
  5. Keep `rasterio.open()` only as an optional secondary fallback if `netCDF4` is unavailable or for non-NetCDF formats.
  6. Mirror the exact same `netCDF4.Dataset` validation logic inside `_create_subprocess_validator_script()` so both `use_subprocess=True` and `use_subprocess=False` behave identically.

### 1.2 Fix `ImportError` Handler in Subprocess Validator
* **Why:** In `_create_subprocess_validator_script()`, `ValidationResult` is defined inside the `try:` block and `pickle` is never imported, causing the `except ImportError:` block to crash with a `NameError`.
* **Implementation Steps:**
  1. Replace the broken `ValidationResult` / `pickle` code in the outer `except ImportError as e:` block with plain JSON serialization:
     ```python
     except ImportError as e:
         error_result = {
             "is_valid": False,
             "filename": sys.argv[1] if len(sys.argv) > 1 else "unknown",
             "errors": [f"Missing dependencies in validator subprocess: {e}"],
             "warnings": [],
             "metadata": {},
         }
         if len(sys.argv) > 2:
             try:
                 with open(sys.argv[2], "w") as f:
                     json.dump(error_result, f)
             except Exception:
                 pass
         sys.exit(1)
     ```

## Phase 2: `netCDF4` Fallback Reader in `GEOS5FPGranule`
**Target File:** `GEOS5FP/GEOS5FP_granule.py`

### 2.1 Prevent Deletion of Valid Files When GDAL Lacks HDF5 Support
* **Why:** `GEOS5FPGranule.read()` currently catches *all* exceptions from `Raster.open(f'netcdf:"{self.filename_absolute}":{variable}')` and immediately deletes `self.filename`, assuming file corruption.
* **Implementation Steps:**
  1. In `GEOS5FPGranule.read()`, inspect the exception raised by `Raster.open()`.
  2. If the error message indicates a missing GDAL driver or unrecognized format (`"gdal_HDF5.so"`, `"not recognized as being in a supported file format"`, or `"HDF5"`), invoke a helper method `self._read_via_netcdf4(variable, geometry, resampling, nodata)`.
  3. Inside `_read_via_netcdf4()`:
     * Open `self.filename_absolute` with `netCDF4.Dataset(..., mode="r")`.
     * Verify `variable` exists in `ds.variables` (if missing, raise `GEOS5FPGranuleNotAvailable` without deleting unless the file itself is unreadable).
     * Read the array (`np.squeeze(np.ma.filled(var[:], np.nan))`) and `lat`/`lon` coordinates.
     * Flip the array vertically (`arr = arr[::-1, :]`) if `lat` is ordered South-to-North (`lats[0] < lats[-1]`), matching standard North-up raster orientation.
     * Construct a `RasterGrid` (`EPSG:4326`) from the coordinate spacing and bounds, wrap `arr` in `rasters.Raster(arr, geometry=grid, nodata=nodata)`, and resample via `data.to_geometry(geometry, resampling=resampling)` if `geometry is not None`.
  4. Only delete `self.filename` (using `_safe_remove`) if *both* `Raster.open()` and `netCDF4.Dataset()` confirm the file cannot be opened or is truncated/corrupted.

## Phase 3: Fix Query Routing, `MultiPoint` Handling, and Computed Albedo Variables
**Target Files:** `GEOS5FP/constants.py`, `GEOS5FP/GEOS5FP_connection.py`, `GEOS5FP/query.py`

### 3.1 Register & Align Computed Albedo Variables
* **Target:** `GEOS5FP/constants.py` & `GEOS5FP/query.py`
* **Implementation Steps:**
  1. Add `'albedo_visible'` and `'albedo_NIR'` to `COMPUTED_VARIABLES` in `GEOS5FP/constants.py`.
  2. Update `GEOS5FP/query.py` so `albedo_visible` and `albedo_NIR` compute `ALBVISDR` and `ALBNIRDR` respectively (matching the docstrings in `GEOS5FPConnection.albedo_visible` and `GEOS5FPConnection.albedo_NIR`, rather than `ALBEDO / ALBVISDR`).
  3. Add support for `albedo_visible` and `albedo_NIR` in `GEOS5FPConnection` raster paths (e.g., returning `self.ALBVISDR(...)` and `self.ALBNIRDR(...)` when queried over a `RasterGeometry`).

### 3.2 Fix Single-Time `MultiPoint` Queries
* **Target:** `GEOS5FP/query.py` (lines ~670–745)
* **Implementation Steps:**
  1. Replace the single-point extraction (`unwrapped_geom.geoms[0]`) in the single-time point query branch with `points = extract_points(geometry)`.
  2. Loop over all `(pt_lat, pt_lon)` pairs in `points` (or reuse the batch coordinate grouping logic) so that passing a `MultiPoint` with $N$ points returns an array/GeoDataFrame of length $N$ rather than truncating to index `0`.

### 3.3 Restore Raster Snapshot Routing in `query()`
* **Target:** `GEOS5FP/GEOS5FP_connection.py` & `GEOS5FP/query.py`
* **Implementation Steps:**
  1. Pass `connection: GEOS5FPConnection = None` (or bind `query` as a method on `GEOS5FPConnection` while keeping a module-level wrapper) so `query()` has access to `self.variable()` and `self.interpolate()`.
  2. Replace the `NotImplementedError` fallback at the end of `query.py` for single-timestamp non-point queries:
     * If `target_variables` is a single known variable in `GEOS5FP_VARIABLES` (and `dataset is None`), delegate to `connection.variable(...)` forwarding `time_UTC`, `geometry`, `resampling`, `interval`, `expected_hours`, `min_value`, `max_value`, `exclude_values`, `cmap`, `clip_min`, and `clip_max`.
     * If `dataset` is explicitly provided (raw variable query), delegate to `connection.interpolate(time_UTC=time_UTC, product=dataset, variable=raw_var, geometry=geometry, resampling=resampling, ...)`.
     * If `target_variables` is a computed variable (`Ta_C`, `RH`, `wind_speed_mps`, `albedo_visible`, `albedo_NIR`, etc.), invoke the corresponding method on `connection`.

## Phase 4: Verification & Automated Test Suite Updates
**Target Directory:** `tests/`

### 4.1 New & Updated Unit Tests
1. **`tests/test_validate_GEOS5FP_NetCDF_file.py`:**
   * Create a real synthetic `.nc4` file in `tmp_path` using `netCDF4.Dataset` (with `lat`, `lon`, and a 2D variable).
   * Mock `rasterio.open` to raise `RasterioIOError("not recognized as being in a supported file format. It could have been recognized by driver HDF5, but plugin gdal_HDF5.so is not available")` and assert `validate_GEOS5FP_NetCDF_file()` still returns `is_valid=True` for both `use_subprocess=False` and `use_subprocess=True`.
   * Test the subprocess `ImportError` path to verify it returns a valid `GEOS5FPValidationResult(is_valid=False)` without crashing.
2. **`tests/test_granule_read.py` (new test module):**
   * Verify `GEOS5FPGranule.read()` falls back to `netCDF4` when `Raster.open` fails with a missing `gdal_HDF5.so` error, preserves the `.nc4` file on disk, and returns a properly georeferenced `Raster` (including North-up orientation check and resampling to a target `RasterGeometry`).
   * Verify genuinely corrupted files still trigger removal and raise `GEOS5FPGranuleNotAvailable`.
3. **`tests/test_variable_queries.py` & `tests/test_geometry.py`:**
   * Ensure existing tests (`test_query_routes_single_raster_snapshot_to_variable`, `test_query_routes_raw_single_raster_snapshot_to_interpolate`) pass.
   * Add unit tests for `MultiPoint` single-time queries returning all $N$ points and for `albedo_visible` / `albedo_NIR` in `COMPUTED_VARIABLES`.

### 4.2 Execution Order & Rollout
1. Implement **Phase 1** (`validate_GEOS5FP_NetCDF_file.py`) and **Phase 2** (`GEOS5FP_granule.py`) first to immediately unblock containerized pipelines lacking `gdal_HDF5.so`.
2. Implement **Phase 3** (`constants.py`, `GEOS5FP_connection.py`, `query.py`) to restore raster snapshot routing and `MultiPoint` consistency.
3. Run `pytest` across the full test suite and verify zero regressions before tagging a patch/minor release in `pyproject.toml`.
